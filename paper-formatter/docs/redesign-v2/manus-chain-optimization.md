# Manus Interaction Optimization For Paper Formatter

## Goal

把论文排版链路从“黑盒处理”优化为“玻璃盒协作”：用户始终知道系统正在检查什么、依据什么、改了哪里、何时需要自己确认，以及下载前是否仍有风险。

## Five Dimensions

| 维度 | 论文排版落点 | 关键输出 |
| --- | --- | --- |
| 信任建立 | Step3 解析、Step4 写回、Step5 确认 | 工作证据、流式输出、确定分母、三态状态 |
| 文案系统 | 顶部胶囊 + 右侧面板 | 胶囊讲用户目标，面板讲操作事实 |
| 结构设计 | Step1-6 准入链 | 前步不通，后步不启动；失败精确卡点 |
| 底层规律 | 3-5 个可扫读节点 | 降低等待焦虑，保持决策主权 |
| 迁移应用 | 规则、修复、下载闭环 | 每一步都有可验收的结果物 |

## Ten Principles Mapped To The Product

1. 工作证据展示：Step3 显示“时间 + 操作 + 对象”，Step4 显示“页码 + finding + rule + 写回动作”，Step5 显示“确认结果 + 下载门槛”。
2. 流式打字机输出：长等待不使用空转圈；解析、修复、生成报告都要有逐步出现的解释文本。
3. 进度分母锚定：每个阶段开始时给出分母，例如“结构识别 4/4”“发现项写回 3/8”“人工确认 5/8”。
4. 状态三态极简化：完成、进行中、等待/需确认；避免把用户暴露给内部技术状态。
5. 多步归并为单意图：胶囊只写用户目标，例如“正在定位送审风险”；面板记录实际操作，例如“解析标题结构”“匹配学校规则”。
6. 标题四层粒度：通道层=文件可读，数据层=结构可用，判断层=规则命中，交付层=修复稿/报告可下载。
7. 准入递进验证链：文件不合格不进入学校规则，规则未确定不进入解析，解析未完成不进入修复，确认未完成不开放定稿下载。
8. 双 Agent 链路分离：自动修复链只做可回退格式写回；人工确认链负责最终决策，不把“系统建议”和“用户确认”混成一步。
9. ConfirmGate 隔离不可逆动作：下载定稿前必须同屏展示“改了多少、未确认多少、正文是否改动、将得到什么文件”。
10. 上下文锚定卡片：Step4/Step5 顶部固定显示当前文档、学校规则、国标版本、当前阶段，不让用户丢失上下文。

## Implementation Batches

### P0: Glass Box Core

- Step3 结果页右侧第一层必须是“主链路轨道”：`Step3 检查 -> Step4 写回 -> Step5 确认门`，并用动效标明下一步，而不是只展示内部证据。
- Step3 结果页右侧第二层增加“准入链 + 工作证据”面板，明确结构识别、规则匹配、证据归档、工作台生成四个节点。
- Step4 完成态保留流式摘要，并覆盖 0 发现浏览模式。
- Step5 下载前增加 ConfirmGate 汇总卡，以正式门槛替代普通下载按钮。

### P1: Copy Architecture

- 建立胶囊文案表：每个阶段只使用“动词 + 用户目标”。
- 建立面板文案表：每条 evidence 使用“时间/顺序 + 操作类型 + 具体对象”。
- 所有 finding、rule、action 文案通过结构化字段生成，避免关键词猜测。

### P2: Failure And Recovery

- 每个准入节点提供失败状态与修复建议。
- 旧版 `.doc`、缺学校规则、解析超时、修复服务不可用分别落到不同卡点。
- 保留“继续浏览”和“重新选择/上传”的安全出口。
