## Task 2-1：步骤标签学生语言化 + 等待反馈

### 问题
"解析"、"差异"这些技术词汇对本科生毫无意义。解析等待期间无进度反馈，学生不知道系统在干嘛。

### 改造内容

**1. 步骤标签替换**

| 原标签 | 新标签 | 说明 |
|--------|--------|------|
| 上传 | 上传论文 | — |
| 规范 | 选择学校 | — |
| 解析 | 正在检查... | 仅在进行中显示，完成后变为 ✓ 已检查 |
| 差异 | 查看修改 | 核心步骤 |
| 导出 | 下载定稿 | 动作导向 |

**2. 解析等待阶段**

进入"正在检查..."步骤时：
- 主区域显示骨架屏（模拟最终页面布局的灰色占位块）
- 骨架屏上方显示滚动文案（每 2 秒切换一条）：
  ```
  "正在检查页边距..."
  "正在核对字体字号..."
  "正在验证参考文献格式..."
  "正在比对目录结构..."
  "即将完成..."
  ```
- 文案用 fade 动画切换（opacity 0→1→0，单条持续 2s）
- 步骤节点上显示旋转 loading 图标（16px spinner）

**3. 步骤间过渡文案**

从"选择学校"进入"查看修改"时，在主区域顶部显示一行过渡说明（持续展示，不消失）：

```
已按《复旦大学 管理学院 v2024.01》规范完成检查
```

- 12px 灰色文字，位于预览区标题上方
- 学校名称加粗

## Task 2-2：通过项默认折叠 + "需确认" 过滤 Tab

### 问题
14 条通过规则对学生是噪音，和 3 条复核项混在一起，学生要逐个展开才能找到需要处理的项。

### 改造内容

**1. 右侧面板顶部增加过滤 Tab**

位置：汇总卡片下方、分类列表上方。

```
[ 需确认 (3) ]    [ 全部 (17) ]    [ 已处理 (0) ]
```

- 默认激活「需确认」
- 「需确认」只展示 status=review 或 status=fail 的规则
- 「已处理」展示 userAction=accepted 或 userAction=ignored 的规则
- 「全部」展示所有规则
- Tab 上的数字实时更新

**2. 分类折叠策略**

在「全部」Tab 下：
- 含复核/失败项的分类：默认展开
- 纯通过的分类：默认折叠，收缩为单行
  ```
  ✓ 页面 · 2项全部通过          ▸
  ```
  - 绿色 ✓ + 灰色文字 + 右侧折叠箭头
  - 点击可展开查看详情

在「需确认」Tab 下：
- 只展示含待确认项的分类，全通过分类完全隐藏
- 每个分类自动展开

**3. 分类头部批量操作**

每个含复核项的分类头部增加快捷操作：
```
⚠ 样式 · ✓4  ⚠1                [ 全部接受 ]   ▾
```
- "全部接受"仅作用于该分类下的复核项
- 点击后复用 Task 1-3 的确认弹窗机制

## Task 2-3：规则按文档位置分类（默认视角）

### 问题
右侧面板的分类（页面、样式、分节&页码、图表&题注、目录&域、参考文献）是排版术语，不是学生的心智模型。学生按"封面→正文→参考文献"思考，不按"页码→行距→题注"思考。

### 改造内容

**1. 增加分组视角切换**

在过滤 Tab 下方增加次级切换：
```
分组方式：[ 按位置 ▾ ]
              ├─ 按文档位置（默认）
              └─ 按规则类型
```

- 默认选中「按文档位置」
- 下拉选择，不用 tab（避免 tab 过多）

**2. 按文档位置分组方案**

| 分组名 | 映射的文档区域 | 说明 |
|--------|---------------|------|
| 封面 | 标题页 | — |
| 声明页 | 原创性声明 | — |
| 摘要 | 中英文摘要 | — |
| 目录 | 目录页 | — |
| 正文 | 章节正文 | 含行距/字体/标题层级等 |
| 图表 | 正文中的图表 | 题注、编号、位置 |
| 参考文献 | 参考文献列表 | 格式、编号、排序 |
| 附录 | 附录（如有） | — |
| 全局 | 跨区域规则 | 页边距、页眉页脚、装订线等 |

每个分组下聚合该区域涉及的所有规则（不论规则原始分类是"样式"还是"页码"）。

**3. 分组名去术语化**

| 原名 | 新名 |
|------|------|
| 分节&页码 | 页码设置 |
| 图表&题注 | 图表格式 |
| 目录&域 | 目录 |

这些仅在"按规则类型"视角下使用。

### 数据依赖
```typescript
interface RuleHitItem {
  // ...existing fields...
  documentSection: 'cover' | 'declaration' | 'abstract' | 'toc' | 'body' | 'figure' | 'reference' | 'appendix' | 'global';
}
```

后端需为每条规则增加 `documentSection` 字段。如果后端暂不支持，前端可用 mapping table 从 `category + pageIndex` 推断：
```typescript
function inferSection(rule: RuleHitItem): string {
  if (rule.category === 'reference') return 'reference';
  if (rule.category === 'caption') return 'figure';
  if (rule.category === 'toc') return 'toc';
  if (rule.location.pageIndex === 0) return 'cover';
  if (rule.location.pageIndex === 1) return 'declaration';
  // ...fallback
  return 'body';
}
```

## Task 2-4：错误状态与边界场景兜底

### 问题
本科生上传的文档千奇百怪，系统需要优雅地处理异常，否则第一次使用就流失。

### 改造内容

**1. 上传阶段错误处理**

| 场景 | 提示文案 | 附加操作 |
|------|---------|---------|
| 非 .docx 文件 | "请上传 .docx 格式的 Word 文档" | 如为 .pdf，额外提示"PDF 文件需先转为 Word 格式" |
| 文件 > 50MB | "文件过大（当前 XXmb），请压缩图片后重新上传" | 可选：提供压缩指引链接 |
| 加密/受保护文件 | "该文件已加密，请移除密码保护后重新上传" | — |
| 网络中断 | "上传失败，请检查网络后重试" | [ 重试 ] 按钮 |

样式：
- 错误提示出现在上传区域内部（替代上传按钮位置）
- 红色左边框 + 浅红背景 + 错误图标
- 3 秒后不自动消失，需用户重新选择文件才清除

**2. 解析阶段错误处理**

| 场景 | 处理方式 |
|------|---------|
| 接口超时（>30s） | 显示"检查时间较长，请稍候..."，60s 后显示 [ 重试 ] 按钮 |
| 接口报错 | "检查过程出错，请重试。如多次失败请联系客服" + [ 重试 ] |
| 解析成功但规则引擎无法匹配规范 | 回退到 Step2 提示"未能匹配到学校规范，请手动选择" |

**3. 大面积失败的柔性处理**

当失败率 > 50%（失败项 / 总规则数 > 0.5）时，不直接展示满屏红色。改为先展示引导卡片：

```
┌─────────────────────────────────────────────────┐
│                                                  │
│  📋 你的文档结构与学校规范差异较大                │
│                                                  │
│  建议先确认以下基础项，修改后重新上传：           │
│                                                  │
│  □ 是否包含标题页（封面）？                      │
│  □ 是否包含目录？                                │
│  □ 章节标题是否使用了 Word 标题样式？             │
│  □ 参考文献是否使用了自动编号？                   │
│                                                  │
│  [ 我已了解，查看详细结果 ]    [ 重新上传 ]      │
│                                                  │
└─────────────────────────────────────────────────┘
```

- 点击"查看详细结果"后正常展示规则报告（含大量红色）
- 点击"重新上传"回到 Step1

**4. 空数据状态**

规则引擎返回 0 条规则时：
```
你的文档暂无可检测的格式规则。
可能原因：文档内容过少或结构不完整。
```
