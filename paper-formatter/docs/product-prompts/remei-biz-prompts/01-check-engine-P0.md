## Task 1-1：上传 + 学校规范匹配

### 产品逻辑

用户进入首页 → 拖拽或点击上传 .docx → 系统自动识别学校 → 用户确认 → 开始体检

### 交互规格

**1. 上传区**

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│                                              │
│         📄 拖拽论文到这里                     │
│            或 点击选择文件                    │
│                                              │
│         支持 .docx 格式，不超过 50MB          │
│                                              │
│    ✅ 不会修改你的原文件，放心上传            │
│                                              │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘

         已支持 128 所高校规范 · 查看列表 →
```

- "不会修改你的原文件" 使用绿色 ✅ 图标，消除恐惧
- 拖拽悬停状态：虚线变实线 + 浅主题色背景 + 文案变"松开即可上传"
- 上传中：文件名 + 进度条（主题色），进度条下方显示"正在上传..."
- 错误处理：
  - 非 .docx → "请上传 .docx 格式的 Word 文档"
  - 超 50MB → "文件过大，请压缩图片后重试"
  - 网络失败 → "上传失败，请检查网络" + [重试]

**2. 学校自动识别**

上传成功后，系统根据文档内容（标题页结构、学校名称、摘要格式）自动推断学校和学院：

```
┌──────────────────────────────────────────────┐
│                                               │
│  🏫 检测到你的学校可能是：                     │
│                                               │
│  ┌─────────────────────────────────┐          │
│  │ 复旦大学 · 管理学院              │  ← 推荐  │
│  │ 匹配度 94%  ⓘ                   │          │
│  │ 规范版本：v2024.01              │          │
│  └─────────────────────────────────┘          │
│                                               │
│  不是你的学校？ 手动选择 →                     │
│                                               │
│              [ 确认，开始检查 ]                │
│                                               │
└──────────────────────────────────────────────┘
```

- 匹配度 ⓘ hover tooltip：
  ```
  基于你文档的标题页结构、摘要格式等特征自动计算。
  94% 表示高度匹配，建议选择此规范。
  ```
- "手动选择"展开学校列表（按地区分组，支持搜索）
- 如果无法识别学校：直接展示手动选择页面

**3. 无规范模式**

学校列表底部增加选项：
```
🔍 浏览模式 · 仅查看文档结构，不进行格式修复
```
灰色边框区分，点击后进入只读体检模式。

### 接口定义

```typescript
// 上传
POST /api/upload
Body: FormData { file: File }
Response: {
  fileId: string;
  fileName: string;
  fileSize: number;
  suggestedSchool?: {
    schoolId: string;
    schoolName: string;
    collegeName: string;
    specVersion: string;
    matchScore: number; // 0-100
  };
  availableSchools: SchoolItem[];
}

interface SchoolItem {
  schoolId: string;
  schoolName: string;
  collegeName: string;
  specVersion: string;
  region: string; // "华东" | "华北" | ...
}
```

## Task 1-2：格式体检执行 + 等待体验

### 产品逻辑

用户确认学校后 → 系统开始体检 → 展示等待动画 → 完成后展示结果

### 交互规格

**1. 等待阶段**

```
┌──────────────────────────────────────────────┐
│                                               │
│          正在检查你的论文格式...               │
│                                               │
│          ━━━━━━━━━━━━━━━━━━━━ 68%             │
│                                               │
│          📐 正在检查页边距...                  │ ← 每 2 秒轮换
│                                               │
└──────────────────────────────────────────────┘
```

轮换文案列表：
```
"正在检查页边距..."
"正在核对字体和字号..."
"正在验证标题层级..."
"正在检查行距和段距..."
"正在核对页码格式..."
"正在验证目录结构..."
"正在检查参考文献格式..."
"即将完成..."
```

- 如果实际进度无法精确获取，使用模拟进度条（0-90% 在预估时间内匀速，收到结果后跳到 100%）
- 超时处理：30 秒后文案变为"文档较大，正在努力检查..."，60 秒后显示 [重试]

**2. 完成过渡**

进度条到 100% 后：
- 200ms 停顿
- 进度条区域替换为结果摘要卡片（fade in 动画）
- 页面自动滚动到结果区域

### 接口定义

```typescript
// 开始体检
POST /api/check
Body: { fileId: string; schoolId: string; specVersion: string }
Response: { taskId: string; estimatedSeconds: number }

// 轮询进度（或 WebSocket）
GET /api/check/{taskId}/status
Response: {
  status: 'processing' | 'completed' | 'failed';
  progress?: number; // 0-100
  currentStep?: string; // "checking_margins"
  result?: CheckResult;
  error?: string;
}
```

## Task 1-3：体检结果展示（免费层核心）

### 产品逻辑

这是免费层最重要的页面。目标：让用户看到足够多的问题，产生"我需要修复"的冲动。

### 交互规格

**1. 得分卡片（顶部，强视觉冲击）**

```
┌──────────────────────────────────────────────┐
│                                               │
│        你的论文格式得分                        │
│                                               │
│            ╭───────╮                          │
│            │       │                          │
│            │  62   │  ← 环形进度，红色区间     │
│            │ /100  │                          │
│            ╰───────╯                          │
│                                               │
│     发现 17 个格式问题，其中 8 个可一键修复    │
│                                               │
│          [ 🔧 立即修复 ]  (免费试用)           │
│                                               │
└──────────────────────────────────────────────┘
```

- 得分颜色：0-59 红色 / 60-79 橙色 / 80-94 绿色 / 95-100 深绿
- 得分数字用大字号（48px+）展示，有计数动画（0 → 62，800ms）
- "立即修复"按钮是主 CTA，引导进入修复流程

**2. 问题清单（得分卡下方）**

按文档位置分组，每组内按严重程度排序：

```
封面（3 个问题）
├── ❌ 封面字体不符合要求    宋体小二 → 黑体二号     [ 🔧 可修复 ]
├── ❌ 学号位置偏移          向右偏移 12mm            [ 🔧 可修复 ]
└── ⚠️ 日期格式不一致        2024年6月 → 二〇二四年六月  [ 🔧 可修复 ]

正文（6 个问题）
├── ❌ 行距不符合规范        1.5倍 → 1.25倍          [ 🔧 可修复 ]
├── ❌ 正文字体混乱          含 3 种字体              [ 🔧 可修复 ]
├── ❌ 标题层级缺失          缺少三级标题样式          [ 🔧 可修复 ]
├── ⚠️ 段前段后间距不一致    0.5行/0行 → 0.5行/0.5行  [ 🔧 可修复 ]
├── ⚠️ 首行缩进不统一        部分段落未缩进           [ 🔧 可修复 ]
└── ℹ️ 建议：正文中有 2 处空行可清理                  [ 手动 ]

参考文献（4 个问题）
├── ❌ 编号格式不符合         [1] → [1]全角括号       [ 🔧 可修复 ]
├── ...
```

- 问题图标：❌ 不合规（红色）/ ⚠️ 建议修改（橙色）/ ℹ️ 提示（灰色）
- "可修复" 标签 = 系统可以自动处理
- "手动" 标签 = 需要用户自己处理（灰色）
- **关键：所有问题免费可见，修复操作才需要付费**

**3. 底部固定 CTA 栏**

```
┌──────────────────────────────────────────────┐
│  发现 17 个问题 · 8 个可一键修复              │
│                              [ 🔧 立即修复 ] │
└──────────────────────────────────────────────┘
```

- 固定在视口底部（sticky bottom）
- 随页面滚动始终可见
- 按钮为主题色，最大视觉权重

### 接口定义

```typescript
interface CheckResult {
  score: number; // 0-100
  totalIssues: number;
  fixableIssues: number;
  manualIssues: number;
  issues: IssueItem[];
}

interface IssueItem {
  id: string;
  severity: 'error' | 'warning' | 'info';
  category: string;           // "font" | "spacing" | "heading" | "margin" | "pageNumber" | ...
  documentSection: string;    // "cover" | "abstract" | "body" | "reference" | ...
  title: string;              // "行距不符合规范"
  currentValue: string;       // "1.5倍"
  targetValue: string;        // "1.25倍"
  fixable: boolean;           // 系统能否自动修复
  pageIndex: number;
  ruleRef?: string;           // "规范第 3.2 条"
}
```
