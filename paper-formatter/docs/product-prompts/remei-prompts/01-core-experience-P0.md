## Task 1-1：全局进度状态 + 人话提示

### 问题
汇总卡片 "14通过 · 3复核 · 0失败" 是系统语言。本科生想知道的是"我改完了没有"。没有完成度指示，没有终态引导。

### 改造目标
学生在 Step4 全程都能看到一句人话状态 + 进度环，处理完所有复核项后有明确的"完成"状态引导导出。

### 交互规格

**1. 汇总区顶部增加状态文案栏**

位置：规则命中报告标题下方、汇总卡片上方。

状态文案逻辑：
```
if (failCount > 0) {
  text = `有 ${failCount} 处格式不达标，需要修改后重新上传`;
  color = --status-fail;
} else if (reviewCount > 0) {
  text = `还有 ${reviewCount} 处需要你确认`;
  color = --status-review;
} else {
  text = `所有格式已确认，可以导出了 🎉`;
  color = --status-pass;
}
```

样式：
- 16px 字号，`font-weight: 500`
- 左侧 4px 色条（颜色跟随状态）
- 底部 8px margin 与汇总卡片分隔

**2. 汇总卡片内增加环形进度**

- 在现有"14通过 / 3复核 / 0失败"三格右侧（或上方）增加一个 48px 环形进度指示器
- 进度 = 已确认数 / 总规则数（已确认 = 通过 + 已接受 + 已忽略）
- 动画：数值变化时 SVG stroke-dashoffset 渐变 300ms

**3. 终态联动**

- 全部确认后（进度 = 100%）：
  - 状态文案变为绿色"可以导出了"
  - 顶部流程条的"导出"步骤节点从灰色变为主题色 + pulse 动画（提示可点击）
  - 环形进度满圈 + ✓ 图标替代百分比数字

### 数据依赖
```typescript
interface SummaryState {
  total: number;
  passed: number;
  reviewed: number;   // 待复核
  failed: number;
  accepted: number;   // 用户已接受
  ignored: number;    // 用户已忽略
  confirmedRatio: number; // (passed + accepted + ignored) / total
}
```

## Task 1-2：默认变更清单模式

### 问题
Before/After 双栏对比对本科生来说"看不懂在比什么"。两栏文本几乎一样，要逐字找差异。学生需要的不是"看全文找不同"，而是"告诉我改了哪几个地方"。

### 改造目标
Step4 默认展示「变更清单」（卡片列表），而非文档全文对比。文档对比保留为"详细对比"入口。

### 交互规格

**1. 预览区默认视图切换**

预览区顶部增加视图切换 tab：
```
[ 📋 变更清单 ]  [ 📄 文档对比 ]
```
- 默认激活「变更清单」
- 「文档对比」即当前的 Before/After 双栏（保留不动）

**2. 变更清单卡片设计**

每张卡片结构：
```
┌─────────────────────────────────────────────┐
│ 📐 行距调整                    第2页 · 正文  │  ← 标题 + 位置标签
│                                              │
│ 修改前：1.5倍行距                            │  ← 灰色文字
│ 修改后：1.25倍行距                           │  ← 主题色文字
│ 依据：《复旦管理学院规范 v2024.01》第3.2条   │  ← 次级灰色，可折叠
│                                              │
│ [查看原文位置]              ✓已通过          │  ← 操作区
└─────────────────────────────────────────────┘
```

卡片分类逻辑：
- 按文档位置分组（封面 → 声明页 → 摘要 → 目录 → 正文 → 参考文献）
- 每组标题显示：`正文（3处修改）`
- 状态为"通过"的卡片默认折叠为单行，只显示标题 + ✓
- 状态为"复核"的卡片默认展开，右侧显示操作按钮（接受/忽略/查看）

**3. "查看原文位置" 联动**

点击后：
- 自动切换到「文档对比」tab
- 滚动到对应页面+位置
- 高亮标记（同 00 文件中的联动规格）
- 3秒后高亮渐隐

**4. 无变更场景**

如果文档完全符合规范（0 处变更）：
```
┌─────────────────────────────────────────────┐
│                                              │
│        ✅ 你的论文格式完全符合规范            │
│           无需任何修改，可以直接导出          │
│                                              │
│              [ 导出定稿 ]                    │
└─────────────────────────────────────────────┘
```

### 数据依赖
```typescript
interface ChangeItem {
  id: string;
  title: string;          // "行距调整"
  category: string;       // "spacing" | "font" | "pageNumber" | "caption" | ...
  documentSection: string; // "cover" | "declaration" | "abstract" | "toc" | "body" | "reference" | "appendix"
  pageIndex: number;
  beforeValue: string;    // "1.5倍行距"
  afterValue: string;     // "1.25倍行距"
  ruleRef?: string;       // "第3.2条"
  status: 'pass' | 'review' | 'fail';
  userAction?: 'accepted' | 'ignored' | null;
}
```

## Task 1-3：操作撤销机制

### 问题
"全部接受"无确认弹窗，已接受/已忽略无法回退。本科生手滑就全部确认了。

### 改造目标
所有用户操作可回退，批量操作有确认，操作后有短暂撤销窗口。

### 交互规格

**1. 单项操作撤销**

- 用户点击"接受"或"忽略"后：
  - 该规则项状态立即变更（乐观更新）
  - 状态标签旁出现「↩ 撤销」按钮，持续显示 10 秒后渐隐
  - 10 秒内点击撤销：状态回退，规则项恢复为"复核"
  - 10 秒后：撤销按钮消失，但仍可通过规则项展开面板中的「重置为待确认」操作回退

- 撤销时的数据流：
  ```
  点击撤销 → 前端回退状态 → PATCH /api/rules/{ruleId}/action { action: "reset" }
  → 后端回退 → 返回更新后汇总 → 前端同步
  ```

**2. 批量操作确认**

- "全部接受"按钮点击后弹出轻量确认弹窗：
  ```
  ┌─────────────────────────────────────────┐
  │                                          │
  │   确定接受全部 3 项待确认的修改？         │
  │                                          │
  │   接受后仍可逐项撤销。                   │
  │                                          │
  │          [ 取消 ]    [ 确定接受 ]         │
  └─────────────────────────────────────────┘
  ```
- 确认后，所有复核项批量变为"已接受"
- 汇总数字批量更新（弹跳动画）
- 底部出现全局撤销条（Toast 样式，固定在底部）：
  ```
  已接受 3 项修改    [ 全部撤销 ]    ━━━━━━━━━ 10s
  ```
  - 进度条 10 秒倒计时
  - 点击"全部撤销"恢复所有项

**3. 已处理项的长期回退**

- 已接受或已忽略的规则项，展开后底部增加次级操作：
  ```
  ──────────────
  ↩ 重置为待确认
  ```
  - 灰色文字，不突出，避免误触
  - 点击后状态回退，汇总数字更新

### 接口定义
```typescript
// 单项操作
PATCH /api/rules/{ruleId}/action
Body: { action: "accept" | "ignore" | "reset", ignoreReason?: string }
Response: { rule: RuleHitItem, summary: SummaryState }

// 批量操作
POST /api/rules/batch-action
Body: { ruleIds: string[], action: "accept" | "reset" }
Response: { rules: RuleHitItem[], summary: SummaryState }
```
