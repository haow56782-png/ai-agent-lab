## Task 3-1：导出前确认摘要页

### 问题
学生最终要把这份文档交给学院查重。他需要确信导出的文件"没问题"。当前点击导出直接下载，缺乏最终确认环节。

### 改造内容

**1. 导出前拦截，展示确认摘要**

点击"下载定稿"（原"导出"）按钮后，不直接下载，先弹出确认面板（非弹窗，在主区域内展示）：

```
┌─────────────────────────────────────────────────────┐
│                                                      │
│  📦 导出确认                                         │
│                                                      │
│  ✅ 格式修改：14 项已自动修正                        │
│  ✅ 手动确认：3 项已由你确认                         │
│  ✅ 正文内容：与原稿完全一致（仅调整了格式，          │
│     未改动任何文字内容）                              │
│                                                      │
│  ───────────────────────────────────────             │
│                                                      │
│  导出文件名：                                        │
│  毕业论文_复旦大学管理学院_20260508.docx             │
│  （可修改 ✎）                                        │
│                                                      │
│  [ 下载修正稿 ]    [ 同时下载原稿对照 ]              │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**2. 各行项说明**

- "格式修改 N 项"：= passCount（系统自动通过的规则数）
- "手动确认 N 项"：= acceptedCount + ignoredCount
- "正文内容与原稿完全一致"：即当前界面中的"正文本指纹一致·零篡改"，翻译为学生语言
- 如果有忽略项，额外显示一行：`⚠ 你忽略了 1 项修改建议（行距设置）`
- 如果有失败项未处理，阻断导出：`❌ 还有 2 项格式不达标，无法导出。请返回处理。`

**3. 文件名自动生成规则**

```
{原文件名去扩展名}_{学校简称}{学院简称}_{YYYYMMDD}.docx
```

示例：`毕业论文_复旦管理学院_20260508.docx`

可编辑：点击 ✎ 后变为 input 框，支持修改文件名。

**4. "同时下载原稿对照"**

点击后额外下载一份未修改的原稿 + 一份修改清单 TXT：
```
修改清单 — remei.docx
学校：复旦大学 | 学院：管理学院 | 规范：v2024.01
检测时间：2026-05-08 14:32

1. [自动修正] 行距调整 | 第2页 正文 | 1.5倍 → 1.25倍
2. [自动修正] 页码格式 | 第1页 前置页 | 阿拉伯数字 → 罗马数字
3. [已接受]   字体修正 | 第3页 摘要 | 宋体 → 黑体小四
...
```

## Task 3-2："零篡改"指标翻译为人话

### 问题
"正文本指纹一致·零篡改"这句话学生完全看不懂。

### 改造内容

**1. 替换文案**

| 原文案 | 新文案 |
|--------|--------|
| 正文本指纹一致·零篡改 | ✅ 你的论文内容未被修改，仅调整了格式 |

**2. 位置与样式**

- 保持在原位置（右上角区域）
- 改为绿色小标签样式（圆角 pill，浅绿底 + 深绿字）
- hover 时展示 tooltip："系统通过文本指纹校验，确认正文内容与原稿完全一致，不涉及任何文字改动"

**3. 异常状态**

如果指纹校验失败（理论上不应出现）：
```
⚠ 内容校验异常，请检查修正稿或联系客服
```
红色标签，同时阻断导出。

## Task 3-3：数字徽标语义化

### 问题
分类折叠区的 "样式 4 [1]" 语义不明，学生不知道 4 和 1 分别代表什么。

### 改造内容

**1. 徽标格式替换**

| 原格式 | 新格式 |
|--------|--------|
| `样式  4  [1]` | `样式  ✓4  ⚠1` |
| `页面  2` | `页面  ✓2` |
| `参考文献  3  [1]` | `参考文献  ✓3  ⚠1` |

**2. 徽标样式**

```css
.badge-pass {
  background: var(--status-pass-bg);
  color: var(--status-pass);
  border-radius: 10px;
  padding: 2px 8px;
  font-size: 12px;
  font-weight: 500;
}

.badge-review {
  background: var(--status-review-bg);
  color: var(--status-review);
  /* 同上结构 */
}

.badge-fail {
  background: var(--status-fail-bg);
  color: var(--status-fail);
  /* 同上结构 */
}
```

- 失败数为 0 时不显示红色徽标
- 复核数为 0 时不显示橙色徽标
- 展开后每条规则项前有 12px 圆形状态图标，颜色与徽标一致

**3. 汇总卡片同步调整**

原来的三格卡片（14通过 / 3复核 / 0失败）也统一使用状态色：
- 通过格：绿色数字 + 浅绿底
- 复核格：橙色数字 + 浅橙底
- 失败格：失败数为 0 时显示灰色"0"（弱化），>0 时红色数字 + 浅红底

## Task 3-4：规则搜索 + 批量展开/收起

### 问题
规则数量多时（17+），学生/导师想找特定规则需要逐个展开。

### 改造内容

**1. 搜索框**

位置：过滤 Tab 下方、分组切换旁。

```
🔍 搜索规则...
```

- 实时模糊匹配 `label` 和 `description` 字段
- 匹配结果：隐藏不匹配的分类和规则项，只展示匹配项（高亮匹配文字）
- 无匹配：显示"未找到相关规则"
- 清空搜索框恢复原始展示
- 搜索框 debounce 200ms

**2. 批量展开/收起**

位置：规则列表顶部右侧（与搜索框同行）。

```
[ 展开全部 ↓ ]  /  [ 收起全部 ↑ ]
```

- 展开全部：所有分类 + 所有规则项展开
- 收起全部：所有分类收起为单行
- 当前为全部展开状态时只显示"收起全部"，反之亦然
