## Task 5-1：上传区优化

### 改造内容

**1. 拖拽上传区**

替换当前 raw `<input type="file">`，改为 dashed dropzone：

```
┌ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┐
│                                          │
│        📄 拖拽论文到这里上传              │
│           或 点击选择文件                 │
│                                          │
│        支持 .docx 格式，不超过 50MB       │
│                                          │
└ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ┘
```

- 虚线边框，2px dashed，颜色 #d4c5a9（配合现有暖色基调）
- 拖拽文件悬停时：边框变实线 + 背景色变浅主题色 + 文案变为"松开即可上传"
- 底部小字："上传后自动检测格式，不会修改你的原文件"

**2. 上传进度**

选择文件后：
- dropzone 内显示文件名 + 上传进度条
- 进度条使用主题色
- 上传完成后自动进入 Step2

**3. 再次上传**

Step4 顶部流程条的"上传论文"步骤可点击回退，或在主区域增加不显眼的"重新上传"入口。

## Task 5-2：最近检测历史

### 问题
本科生的论文不是一次定稿的。每次上传都从零开始，没有历史记录。

### 改造内容

**1. localStorage 存储检测记录**

```typescript
interface CheckHistory {
  id: string;           // uuid
  fileName: string;
  schoolName: string;
  specVersion: string;
  timestamp: number;    // Date.now()
  summary: {
    total: number;
    passed: number;
    reviewed: number;
    failed: number;
  };
  // 不存储完整报告，仅存储摘要
}

// localStorage key: 'remei_check_history'
// 最多保留 10 条，FIFO 淘汰
```

**2. 首页展示**

上传区下方增加"最近检测"区域（有历史记录时才显示）：

```
最近检测
──────────────────────────────────────────
📄 毕业论文.docx                    5月6日
   复旦大学 管理学院 · ✓14 ⚠3 ✗0
   [ 重新上传该文件 ]

📄 毕业论文_v2.docx                 5月3日
   复旦大学 管理学院 · ✓16 ⚠1 ✗0
   [ 重新上传该文件 ]
```

- 卡片点击展开摘要，但不能查看历史报告详情（数据未持久化）
- "重新上传该文件"：由于原文件不存储，实际是预填学校选择后跳转到上传区

**3. 同名文件提示**

上传与历史记录同名的文件时，顶部显示 info toast：
```
检测到你之前上传过同名文档（5月6日），本次将进行新的检测。
```
持续 5 秒后自动消失。

## Task 5-3：首次使用信任建设

### 问题
本科生第一次打开系统，不知道靠不靠谱，能帮到什么程度。

### 改造内容

**1. 上传区微文案**

dropzone 下方增加一行信任文案：
```
已支持 XX 所高校规范  ·  查看支持列表 →
```
- "查看支持列表"点击后弹出 modal，展示已支持的学校列表（按地区分组）
- 如果学校列表数据在后端，用接口拉取；否则前端硬编码

**2. Step2 学校匹配度解释**

当前学校卡片上的 "match 94%" 含义不明。增加解释：

- 在匹配度数字旁增加 ⓘ 图标
- hover/点击 ⓘ 展示 tooltip：
  ```
  匹配度基于你文档的标题页结构、摘要格式、
  参考文献样式等特征自动计算。
  94% 表示高度匹配，建议选择此规范。
  ```

**3. 无规范模式文案优化**

| 原文案 | 新文案 |
|--------|--------|
| 仅检测模式·未选择规范 | 浏览模式 · 仅查看文档结构，不修改格式 |

增加浅灰边框视觉区分，与学校卡片的主题色边框区别开。

## Task 5-4：快捷导航

### 问题
学生处理多个复核项时，需要在规则列表中手动找下一个待处理项。

### 改造内容

**1. "下一个待确认" 导航按钮**

位置：右侧面板底部，固定不滚动（sticky bottom）。

```
┌─────────────────────────────────┐
│  ⏎ 下一个待确认 (2/3)    [ → ] │
└─────────────────────────────────┘
```

- 显示"当前第几个/共几个待确认"
- 点击后：
  - 右侧面板滚动到下一个复核项
  - 自动展开该规则
  - 触发左侧预览区联动（Task 4-1）
- 全部处理完后按钮变为：`✅ 全部已确认  [ 下载定稿 → ]`

**2. 键盘快捷键（可选）**

| 快捷键 | 功能 |
|--------|------|
| `J` | 下一个待确认 |
| `K` | 上一个待确认 |
| `A` | 接受当前项 |
| `I` | 忽略当前项 |
| `Z` | 撤销上一操作 |

- 仅在 Step4 激活
- 右下角增加 `⌨` 图标，hover 显示快捷键列表
- 默认不启用，点击 ⌨ 图标后激活（避免与输入框冲突）
